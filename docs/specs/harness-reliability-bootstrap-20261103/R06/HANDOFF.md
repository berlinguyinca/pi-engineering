## Required shape (name things exactly, keep it small)
- `export type RecoveryRecommendation = "retry" | "hold" | "failover" | "stop" | "review";`
- `export interface RecoveryRecommendInput` — `failure: { class: InferenceFailureClass; retryAfterMs?: number }`, `budget?: RetryBudgetInput` (R03's type), `circuit?: EndpointCircuitSnapshot` (R04's type), `action?: ToolAction` (R05's type), `nowMs: number`, `switchAvailable?: boolean` (a comparable model/endpoint exists to fail over to).
- `export interface RecoveryRecommendResult` — `recommendation: RecoveryRecommendation`, `reason: "permanent_class" | "budget_exhausted" | "server_wait" | "circuit_open" | "no_probe_slot" | "not_replayable" | "unclassified" | "within_budget" | "invalid_input"`, `waitMs: number | null`, `source: "retryBudget" | "endpointCircuit" | "recoverySafety" | "class" | "input"`.
- `export const PERMANENT_CLASSES: ReadonlySet<InferenceFailureClass>` — exactly `authentication`, `authorization`, `billing`, `invalid_request`, `model_not_found`, `request_too_large`, and the header comment must say why (`model_not_found` is the 404 case whose retry counts are granted twice today — see `docs/specs/harness-reliability-bootstrap/RETRY_OWNERS.md` conflict 4 — and this unit never adds a retry grant).
- `export function recommendRecovery(input: RecoveryRecommendInput): RecoveryRecommendResult`.
Order of decisions to implement and test: invalid input (`nowMs` non-finite, or `failure` missing / `class` not in the `InferenceFailureClass` union) → `stop` / `invalid_input` / `waitMs: null` / `source: "input"`; `PERMANENT_CLASSES.has(class)` → `stop` / `permanent_class` / `waitMs: null` / `source: "class"` **regardless of budget or circuit** (this is the "404 does not endlessly retry" clause: even `attempt: 1, maxAttempts: 5` returns `stop`); `class === "unknown"` → `stop` / `unclassified` / `source: "class"`; `class === "rate_limited"` or `"queue_saturated"` or `"model_activating"` → `hold` with `waitMs` equal to the larger of `failure.retryAfterMs` and the budget's computed wait, `source: "server_wait"` when `retryAfterMs` is present and finite, and `recommendation: stop` with `budget_exhausted` when R03 says stop; when `circuit` is supplied → `failover` if the circuit says `allowAttempt: false` and `switchAvailable === true`, `stop` with `circuit_open` if it says `allowAttempt: false` and no switch exists, `stop` with `no_probe_slot` when the circuit reason is `probe_in_flight`; when `action` is supplied → `review` / `not_replayable` / `source: "recoverySafety"` if `classifyReplaySafety(action).replayAllowed === false`; otherwise delegate to R03 → `retry` with its `waitMs` (`source: "retryBudget"`) or `stop` / `budget_exhausted`. `recommendation` is **never** `"retry"` when `circuit` says `allowAttempt: false`, and never `"retry"`/`"hold"` for a permanent class.

## Write tests for exactly these properties (one `it()` per property, dense, no narrative comments)
1. **404 does not endlessly retry.** `model_not_found` with `budget: { maxAttempts: 5, attempt: 1, elapsedMs: 0, baseBackoffMs: 100 }` → `stop`, `reason: "permanent_class"`, `waitMs: null`, `source: "class"`; and the same for each of the other six permanent classes; and adding a healthy `circuit` snapshot plus `switchAvailable: true` still yields `stop`.
2. **429 honours the server wait.** `rate_limited` with `retryAfterMs: 45_000` and a budget whose local backoff would be 100 → `hold` with `waitMs === 45_000`, `source: "server_wait"`; with `retryAfterMs: 5` and a budget that yields 12_800 → `hold` with `waitMs === 12_800`; and with `maxAttempts: 2, attempt: 2` → `stop` / `budget_exhausted` even though `retryAfterMs` is large.
3. **Unknown stops.** `class: "unknown"` → `stop` / `unclassified`; `class: "not_a_real_class"` and a missing `failure` → `stop` / `invalid_input` / `source: "input"`; non-finite `nowMs` → `invalid_input`.
4. **The circuit decides whether the same endpoint may be attempted.** open snapshot past cooldown → `failover` when `switchAvailable: true`, `stop` / `circuit_open` when it is false; an open snapshot still inside cooldown → same two outcomes; a snapshot whose evaluation returns `probe_in_flight` → `stop` / `no_probe_slot`; and never `retry` in any of these four cases.
5. **A non-replayable action goes to review, never to automatic retry.** `action: { name: "bash", writes: true }` on a `network_interruption` → `review` / `not_replayable` / `source: "recoverySafety"`; `action: { name: "mystery_tool" }` likewise; and `action: { name: "read" }` falls through to the budget (`retry`, `source: "retryBudget"`).
6. **Invariants over a table + purity.** For each of the 21 classes × {with a permanent-class check, healthy circuit, open circuit with and without `switchAvailable`, non-replayable action} assert `recommendation === "retry"` implies the circuit allows the attempt and that permanent classes never produce `retry` or `hold`, and report the number of combinations evaluated; plus read the module's own source with `readFileSync` and assert the only `import` lines are from the four permitted siblings and that it contains none of `Date.now`, `Math.random`, `process.env`, `setTimeout`, `fetch`, `writeFile`, `appendFile`.
