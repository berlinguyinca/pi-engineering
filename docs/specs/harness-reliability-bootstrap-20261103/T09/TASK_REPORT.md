## Residual risk / observations carried forward
- **`untracked` inclusion can over-report**: the gate unions `git ls-files --others --exclude-standard` with the committed diff, so a stray build artifact in a contract worktree can block integration for a file that was never committed. Conservative (it blocks, never lets through), but the follow-up should judge *committed* paths for the violation and use untracked only as a warning.
- **Protected list is a constant default, not derived from the manifest**: `PROTECTED_TASK_AUTHORITY_GLOBS` hard-codes the bootstrap layout rather than reading each task's `protected` field, so protection follows repo convention instead of per-task authority. Wiring the per-manifest list needs the manifest/authority plumbing (T01's `taskAuthority` + the runtime), same lineage as the other unwired gates.
- **Gate runs per-attempt, not per-merge**: a contract whose *review* later widens the diff is re-checked on the next attempt (the review path itself still only reports `outOfScope`), so a reviewer-introduced path would surface at the next attempt's gate rather than at merge time.
- **No live executor test**: `scopeIntegrityCheck` is proven purely and the wiring by inspection; an executor-level integration test would need a real mission fixture worktree (out of this unit's budget).
