The real mechanism was the common directory, not the abort signal

  At 4ffa82f3 `commonDir()` returned `/private/private/var/folders/…/<repo>/.git` — the
  physical prefix applied twice, because safeGit points GIT_DIR/GIT_COMMON_DIR/GIT_WORK_TREE
  at Pi's shadow state and `/var` is a symlink to `/private/var` (X08/logs/05). In the same
  process, `git -C <repo> rev-parse --path-format=absolute --git-common-dir` returned the
  correct path (X08/logs/09). Everything derived from the answer — the promotion
  administration lock, the candidate journal, the checkpoint records — failed its mkdir with
  ENOENT, and `withWorktreeSection` reads ENOENT as "the other process's lock is not there
  yet" and queues to `promotionWait.ceilingMs` (600 s per attempt). A file whose scenario
  touches that path several times is therefore killed by any ceiling below it, with no tally
  and no signal — which is what the 240 s capture above shows, and why it looked like a
  promise parked on an interrupt that never arrived.

  The A/B that settles the question (X08/logs/06): at 4ffa82f3, applying ONLY a
  common-directory guard — nothing else, no interrupt, no lease, no scheduler change — the
  file settles and reports 12 tests collected (6 pass, 6 fail on unrelated assertions that
  later commits fixed). At 45d42acb, with no guard, the same file is 12 pass / 0 fail in
  29 s (X08/logs/07). So the abort-signal reading above was plausible and wrong.

Upstream fixes, both now in the base

  61394da7  fix(git): one canonical path for the state dir and the temp root (#582) — the
            state directory and temp root are canonicalized at boot, the same way repository
            discovery already resolves them, so a shadow path built over an unresolved state

  89e747c2  fix(git): translate shadow paths by spelling, so a real path is never doubled

            of `path.resolve`, which re-applied the physical prefix. At this tip the doubled
            prefix no longer reproduces: `commonDir()` is real and equal to a plain git
            answer in every layout probed (X08/logs/11).

Residual hardening on this branch (X08)

  `GitRepo.commonDir()` no longer hands back an answer that names no directory: an answer
  that exists is passed through untouched (it is usually the shadow common dir, which only
  git knows), one that does not exist is repaired from the filesystem layout, and when
  neither resolves the call throws naming the impossible path. Without it, a regression of
  #582 or #602 is invisible at the source and reappears as a 600 s poll; with it, the
  regression is an error at the call site naming what git reported
  (X08/logs/12-neighbour-units.txt, test/unit/git-common-dir-repair.test.ts).
