- **Path**: `test/integration/worker-stream-truncation.test.ts:306-310`
- **Input**: The test asserts `isResilientRuntime(await executor.getModelRuntime()) === true` at line 310, but the `withProbe()` helper at lines 83-131 creates a `PiWorkerExecutor` without setting `PI_INFERENCE_RESILIENCE_ENABLED=1`.
- **Evidence**: The PR flips `DEFAULT_INFERENCE_RESILIENCE.enabled` from `true` to `false` at `src/inference/resilienceConfig.ts:103`. The test implicitly relied on the old default. Unlike the two integration tests (`resilient-inference-integration.test.ts:126`, `resilient-inference-wiring.test.ts:145`) that were updated to pass `PI_INFERENCE_RESILIENCE_ENABLED: "1"` explicitly, this test was not.

- **Severity**: **MAJOR** — the test itself is sound; the production path it covers (resilient stream resume) is real. The default flip silently disabled the production path in this test harness without updating it.
- **FIX REQUIRED**: Add `env: { PI_INFERENCE_RESILIENCE_ENABLED: "1" }` to the `PiWorkerExecutor` options in `withProbe()` or create a dedicated harness for that one test case.

**MINOR (2) — `resolveCommonDir` can throw EACCES/ESTALE from `discoverRepo` without a meaningful message**
- **Path**: `src/git/GitRepo.ts:273-278`
- **Input**: When the `reported` path does not exist, `discoverRepo(repoRoot)` is called. If the repository is on a NFS mount and ESTALE occurs during the discovery, the error bubbles up with no mention of the repository or the reported path.
- **Evidence**: Lines 266-270 handle EACCES/ESTALE for `lstat(reported)` by rethrowing, but line 274's `discoverRepo` call can similarly fail (it reads `.git` or resolves the worktree linkage).
- **Severity**: **MINOR** — the guard exists for macOS `/private/var` doubling, not for stale NFS handles; the error is honest (throws instead of silently accepting a bogus path), just lacks detail.

**MINOR (3) — `pathPolicy.ts` symlink anchor set is case-sensitive; filesystem may not be**
- **Path**: `src/bootstrap/pathPolicy.ts:41,54-56`
- **Input**: On macOS APFS with case-insensitivity, a symlink named `Src` is not equal to a request for `src/foo.ts`. The set lookup at line 41 (`anchors.has(ancestor)`) is string-exact.
- **Evidence**: The policy normalizes paths through `canonicalizeWriteDomain` which does not case-fold (it only strips leading slash and collapses `.`/`..`). A request for `SRC/module.ts` will not match an anchor registered as `src`.
- **Severity**: **MINOR** — the caller must populate `symlinks` from `lstat`, which sees the casing git uses; a mismatch between git's casing and the manifest's casing is unlikely but not impossible.

**NIT (5) — `taskManifest.ts` missing `const` before MICROTASK_CEILING**
