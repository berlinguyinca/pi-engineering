## Residual gaps
- **The flags are self-declared.** `writes` and `external` come from the caller's description of the action; nothing in the harness produces them yet, so today every real tool action would classify as `unknown_tool` (which is the safe answer, but means the classifier has no live inputs). Wiring it needs annotations from the tool surface, which lives outside this unit's allowed paths.
- `READ_ONLY_TOOL_NAMES` is a hard-coded seven-name list that will drift as tools are added; the comment makes adding a name an evidence-requiring policy change, but nothing enforces that.
- A read-only tool that *becomes* mutating through its arguments (e.g. `bash` invoking `grep` is fine, but a future `read` with a `--output` flag would not be) is invisible to name-based classification; the classifier's safety is exactly as good as the name list.
- `replayAllowed` is advisory: no runtime path consults it, so no replay is actually blocked in production yet.
