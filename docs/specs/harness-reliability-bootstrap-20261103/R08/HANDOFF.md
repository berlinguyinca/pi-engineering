## Required shape (name things exactly, keep it small)
- `export const RESOLUTION_SHA: RegExp` — `/^sha256:[0-9a-f]{64}$/`, same shape discipline as `FAILURE_ID`.
- `export type ResolutionStatus = "recovered_temporarily" | "root_cause_resolved" | "unresolved" | "unknown";` and the header comment must state the mapping to `RecoveryOutcome` (a `recovered` durable outcome can only ever support `recovered_temporarily` here, never `root_cause_resolved`).
- `export interface ReproductionEvidence` — `command: string`, `exitCode: number`, `artifact?: string`.
- `export interface PassingCheck` — `command: string`, `exitCode: number`, `artifact: string`.
- `export interface ResolutionEvidenceInput` — `reproduction?: ReproductionEvidence | null`, `patchIdentity?: string`, `settingIdentity?: string`, `passingCheck?: PassingCheck | null`, `scopeAllowed?: boolean`, `changedFiles?: readonly string[]`, `allowedPaths?: readonly string[]`, `postFixStatus?: RecoveryOutcome | null`, `retryCount?: number`, `sameCheckSequencePassed?: boolean`.
- `export interface ResolutionVerdict` — `status: ResolutionStatus`, `resolved: boolean`, `missing: string[]`, `reason: string`, `temporaryBecause: string | null`.
- `export function classifyResolution(input: ResolutionEvidenceInput): ResolutionVerdict`.
Rules, in order: any of `reproduction` absent / `reproduction.exitCode === 0` / `reproduction.command` blank → `unresolved` with `missing` containing `"failing-reproduction"` (a run that already passed proves nothing was fixed); `patchIdentity` or `settingIdentity` present but not matching `RESOLUTION_SHA` → `unresolved` + `"patch-identity"` / `"setting-identity"`; both absent → `unresolved` + both entries; `passingCheck` absent, `exitCode !== 0`, or blank `command`/`artifact` → `unresolved` + `"passing-check"`; `scopeAllowed === false` **or** a `changedFiles` entry outside `allowedPaths` (prefix match, `allowedPaths` empty counts as outside) → `unresolved` + `"scope"`; `postFixStatus` absent or `"unknown"` → `unknown` with `resolved: false`; `postFixStatus === "unresolved"` or `"suppressed"` → `unresolved`; `postFixStatus === "recovered"` → `recovered_temporarily` with `resolved: false` and `temporaryBecause` naming that a recovered durable outcome is evidence of suppression/retry, not of a removed cause, **even when `retryCount` is large** — `retryCount` alone may only ever appear in `reason`, never raise the status; `recovered_temporarily` becomes `root_cause_resolved` (`resolved: true`) **only** when `sameCheckSequencePassed === true`, i.e. the same named check that failed before now passes with identities and scope intact. No input may ever produce `root_cause_resolved` without all five requirements satisfied, and `resolved === true` must imply `status === "root_cause_resolved"`.

## Write tests for exactly these properties (one `it()` per property, dense, no narrative comments)
1. **Retries alone cannot mark root cause resolved.** A complete, well-formed input with `postFixStatus: "recovered"`, `retryCount: 40`, `sameCheckSequencePassed: false` → `status: "recovered_temporarily"`, `resolved: false`, `temporaryBecause` non-null; and the same input with `retryCount: 0`…`500` (a loop) never yields `root_cause_resolved`.
2. **A passing run proves nothing.** `reproduction: null`, `{ command: "x", exitCode: 0 }`, `{ command: "  ", exitCode: 1 }` each → `unresolved` with `"failing-reproduction"` in `missing`, even when patch/setting identities, passing check, scope and `postFixStatus: "recovered"` plus `sameCheckSequencePassed: true` are all valid.
3. **Identity is shape, not text.** `patchIdentity: "abc123"` and `settingIdentity: "patched"` → `unresolved` naming the offending entry; a `sha256:` + 63 hex and a `sha256:` + 64 **uppercase** digits both fail `RESOLUTION_SHA`; the canonical 64-lowercase-hex form passes and is not rewritten in the verdict.
4. **Scope is validated.** `scopeAllowed: false` → `unresolved` + `"scope"`; `changedFiles: ["src/a.ts", "docs/x.md"]` against `allowedPaths: ["src/a.ts"]` → `"scope"`; `allowedPaths: []` with any changed file → `"scope"`; a changed file that is a prefix-extension of an allowed path (`"src/a.ts.bak"` vs `"src/a.ts"`) → `"scope"`; and all-valid scope plus `postFixStatus: "recovered"` plus `sameCheckSequencePassed: true` → `root_cause_resolved` / `resolved: true`.
5. **Missing post-fix status is unknown, not resolved.** `postFixStatus` absent, `null` and `"unknown"` → `status: "unknown"`, `resolved: false`; `"unresolved"` and `"suppressed"` → `unresolved`; and no case in the whole test file asserts `resolved: true` unless all five requirements are present.
6. **The invariant over a table + purity.** Loop `postFixStatus` over all five `RecoveryOutcome`-plus-absent values × `sameCheckSequencePassed` true/false × reproduction present/absent (report the count), asserting `resolved === (status === "root_cause_resolved")`, that `root_cause_resolved` appears only with a failing reproduction, both valid identities, a passing check, scope allowed and `sameCheckSequencePassed` true, and that `missing` is empty exactly when `resolved` is true; plus read the module's own source with `readFileSync` asserting no `writeFile`, `appendFile`, `console.`, `Date.now`, `Math.random`, `process.env`, `setTimeout`, `fetch` and that the only import line is the type-only `RecoveryOutcome` import.
