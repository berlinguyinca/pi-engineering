## Verified handoff schema (checked first, as the delta requires)
`HandoffArtifact` (`src/plannerWorker/types.ts:153-174`) carries `kind, mission_id, task_id, from_role, to_role, mission_summary, architectural_context[], objective, relevant_files[], decisions[], constraints[], acceptance[], verification[], scope, dependency_results[], correction?, worker_outcome?, token_estimate` — there is **no** field for a contract hash, and none may be added. `buildHandoff()` (`handoff.ts:51`) already clips `mission_summary` (1 500 chars), dependency summaries, and `worker_outcome.diff` (24 000 chars), and never carries a reasoning transcript; `renderHandoff()` drops `token_estimate` from the YAML and puts the diff after a `--- diff ---` separator. So authority must travel in a **separate sealed envelope created in this file**, not inside the artifact.

## Required behaviour (all additive to handoff.ts)
1. `const MAX_TRANSCRIPT_CHARS = 2_000;` (or similar named bound) and
   `interface HandoffAuthority { authority_hash: string; objective_sha256: string; constraints_sha256: string; acceptance_sha256: string; scope_sha256: string; transcript_excerpt: string; transcript_truncated: boolean; transcript_chars: number }`
   `interface SealedHandoff { handoff: HandoffArtifact; authority: HandoffAuthority }`.
2. `sealHandoff(handoff: HandoffArtifact, transcript?: unknown): SealedHandoff` — pure and deterministic. Hash each authority-bearing part with the repo's canonical hasher (`canonicalHash` from `src/bootstrap/taskAuthority.ts`; say in a comment that this is the same canonicalization T01 uses so a handoff hash is comparable to a task authority hash): `objective` (string), `constraints` (sorted copy of the array), `acceptance` (sorted copy), `scope` (the object). `authority_hash` = `canonicalHash({ objective, constraints, acceptance, scope })` — note explicitly that `mission_summary`, `decisions`, `architectural_context`, `dependency_results`, `correction`, `worker_outcome` and `token_estimate` are **not** authority-bearing, which is what lets a resumed worker get a new summary without changing authority. The transcript argument is bounded: `transcript_excerpt` = first `MAX_TRANSCRIPT_CHARS` chars of a trimmed string (empty string when the argument is not a string), `transcript_truncated` = whether it was clipped, `transcript_chars` = the trimmed length. The full transcript is never retained anywhere in the envelope.
3. `verifyHandoffAuthority(sealed: SealedHandoff, expectedAuthorityHash?: unknown): { ok: true; authority: HandoffAuthority } | { ok: false; reasons: string[]; authority: HandoffAuthority }` — recompute the four field hashes and the aggregate from `sealed.handoff`; report every diverged field by name (`objective`, `constraints`, `acceptance`, `scope`) in `reasons` (e.g. `objective diverged: <recorded> != <recomputed>`); when `expectedAuthorityHash` is a non-empty string and differs from the recomputed aggregate, add a reason naming both hashes; when it is absent or not a string, add `expected authority hash missing` (fail closed — a resumed worker must always present one). Never throw; never mutate the input.
4. `resumeHandoff(env: unknown, expectedAuthorityHash?: unknown)` — accept only `{ handoff, authority }`-shaped input (otherwise `{ ok: false, reasons: ["malformed envelope"] }`), and **reject tampering with the envelope itself**: recompute the authority from `env.handoff` and require the envelope's recorded `*_sha256` fields and `authority_hash` to match the recomputation (an envelope whose recorded hash disagrees with the handoff it carries is rejected, naming which part was altered), then apply step 3 against `expectedAuthorityHash`. This is the "reject altered authority on resumed worker" clause.
5. Keep `buildHandoff`, `renderHandoff`, `estimateTokens`, `WORKER_INSTRUCTION` and every existing behaviour byte-identical — existing callers and tests must keep passing (typecheck plus the existing planner handoff tests if you choose to run one; do not run the whole suite).
6. No scores, percentages or confidence values anywhere; reasons are factual strings naming hashes/fields.
