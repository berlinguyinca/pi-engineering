## What the unit provides
`evaluateTaskAlignment(input): AlignmentSignal[]`, pure and deterministic, over `allowedScope` / `declaredTasks` / `allowedDependencies` / `actions` / `acceptance` / `stagnationIterations`. The four kinds are exactly the delta's four: `out_of_scope_write` (only for actions the caller marks `mutating`, glob-checked with the existing `matchesGlob` from `plannerWorker/contract.ts:298`, evidence naming the target and the allowed globs it was checked against), `unrelated_dependency` (trimmed, case-insensitive against the authorized list; `authorized: none` when the list is empty), `task_expansion` (task id not among `declaredTasks`, evidence naming both), `acceptance_stagnation` (criteria unadvanced by at least the threshold relative to the highest observed action iteration, flagged once, subject listing the unadvanced criteria). Output is sorted (kind → subject → iteration), deduplicated, and carries **only observable facts**: `grep -niE "confidence|score|certainty|percent|[0-9]+%"` over the module returns nothing, and evidence strings quote iteration numbers, paths, dependency names and thresholds. Invalid thresholds (`-5`, `NaN`) fall back to the documented default rather than throwing; empty inputs are inert.

## Residual risk / observations carried forward
- **Detector is not yet observed in a live path**: nothing calls `evaluateTaskAlignment` (`src/aps/observability.ts`, `workerActivity.ts` and the runtime are outside this unit), so a real run still emits no deviation signals — same wiring debt as T05's `requiredContextGate`, T06's provenance fields and T03/T04's broker inputs. T09 (gate must consume task evidence) is the natural consumer.
- **`mutating` is caller-supplied**: the module trusts the caller's flag (using `isMutatingTool` only as a fallback), so a mis-classified action silently becomes a read and escapes scope checks — the wiring unit must derive it from the same tool taxonomy the result gate uses.
- **Stagnation is coarse by design**: `progressedAtIteration` is a last-progress map, so the signal reports *how far behind the last recorded progress the actions ran* and lists all criteria, not per-criterion histories; a criterion that advanced then stalled looks identical to one that never started. Fine as an evidence signal; a real acceptance ledger would refine it.
- **Dependency authority comes from an explicit list**: a task that legitimately needs a new package must declare it, otherwise it is flagged — conservative by design (the flag is evidence, not a verdict).
