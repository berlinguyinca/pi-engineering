## Design constraints that mattered, and how they were met
The repo already has a circuit breaker — the mutable, **mission-scoped** `CircuitBreaker` inside `src/resilience/MissionSupervisor.ts` (class `:55`, gated `:158-171` with `tryHalfOpen()` / `recordSuccess()` / `recordFailure()`). ## Residual gaps
- **Nothing drives the snapshots yet.** No production caller holds `EndpointCircuitSnapshot`s or calls `evaluateEndpointCircuit`; `MissionSupervisor`'s breaker remains the only live breaker, and adoption would cross `src/resilience/**`, `src/workers/**` and `src/models/**` — all deny-listed here. So this is a contract plus its proof, not a behaviour change.
- `probeLimit` is declared but effectively fixed at 1 (`probeInFlight` is a boolean); a future multi-probe policy needs a counter, and the type advertises a knob the implementation cannot vary.
- The circuit has no notion of *partial* recovery: a single success from `half_open` fully closes and resets the streak, so an endpoint flapping at 1-in-2 will never stay open. Whether that is right for `model_not_found` (usually permanent until config changes) is an open policy question I did not resolve silently.
- Endpoint keys are bounded by the **caller** using `noteEndpointKey`; nothing enforces that a caller actually does, so unbounded snapshot maps remain possible outside this module.
