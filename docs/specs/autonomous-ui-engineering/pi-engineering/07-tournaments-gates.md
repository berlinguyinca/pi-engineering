# Candidate tournaments and Pareto gates

For uncertain/high-impact changes create multiple isolated-worktree candidates using existing Pi tournament/subagent infrastructure. Run the same evaluation battery against baseline and candidates.

Acceptance requires target improvement plus no critical task/accessibility/behavior regression, deterministic tests pass, performance and complexity within budgets, protected semantics/contracts intact, and disagreement resolved/below threshold.

Do not select by one aesthetic/aggregate score. Models never approve their own work. Low-risk proven fixes may auto-merge; major IA/product-semantic/destructive/security-sensitive changes require approval unless repository policy explicitly allows them.
